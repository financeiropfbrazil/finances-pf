## 0. Protocolo de sessão

**Início:** ler este arquivo inteiro; cumprir o início de sessão do CLAUDE.md (remote, `git pull`, fingerprint do
Supabase antes de qualquer escrita); identificar a tarefa (ex.: "NFSE-0.3") — se o Pedro não indicou, perguntar.

**Durante:** uma tarefa por vez; problema → causa → impacto → solução → risco antes de executar; nunca assumir schema;
**toda escrita (banco, deploy, erp-proxy) com OK explícito do Pedro**. Tarefas registradas são imutáveis — mudanças
viram tarefas novas (Ajuste/Correção).
- **erp-proxy:** repo separado, edição pelo **GitHub Web** pelo Pedro (clone local sempre defasado), deploy automático
  no Render. O código sai daqui pronto em `docs/nfse/erp-proxy/`, compilado contra o `origin/main` atual.
- **Banco:** SQL em arquivo (`docs/nfse/NFSE-x.y-*.sql`) com pré-voo e rollback; aplicado pelo MCP de escrita
  (conector `0e14dbb7`, fingerprint antes) ou pelo Pedro no SQL Editor. Nunca `supabase db push`.
- **Edge Functions:** deploy pelo CLI com `--project-ref hbtggrbauguukewiknew`, `verify_jwt` declarado no
  `config.toml`; provar versão + probe 401 + carimbo de versão no `sync_runs`.

**Fim de tarefa:** atualizar §3 (status) e §6 (diário); build + type-check quando houver frontend; commit pequeno com
este arquivo; push só com OK do Pedro; frontend publicado só com Publish manual no Lovable.
